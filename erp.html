Proof of delivery

Provider otomatis, webhook bertanda tangan, tracking live, unggah Storage dari UI, refund/kompensasi, dan rekonsiliasi biaya ke Finance tetap belum diaktifkan. Jangan memasukkan booking provider eksternal sebelum integrasinya disetujui.

Kompensasi efektif & payroll

Rate per jam harus disetujui terpisah dan efektif pada tanggal tertentu. Payroll dihitung dari timesheet approved, lalu diposting dan direkonsiliasi melalui finance_journal_entries dengan actor independen.

Payroll run

Generate → submit independen → approve independen → siapkan jurnal → post → reconcile. Pembayaran eksternal tetap ditunda sampai adapter provider disetujui.

Mapping akun Payroll → Finance

Mapping per cabang harus diajukan dan disetujui oleh aktor berbeda sebelum jurnal dapat disiapkan.

Payroll dihitung dari timesheet approved dan rate kompensasi efektif. Posting Finance memakai tabel finance_journal_entries yang ada; setiap tahap prepare, post, dan reconcile memiliki actor independen. Rekonsiliasi menghitung hash dari baris jurnal yang benar-benar posted. Pembayaran payroll hanya dapat direkonsiliasi setelah provider approved, beneficiary approved, batch disetujui, dan signed event diterima untuk setiap item.

Payroll payment & provider reconciliation

Hanya dapat disiapkan dari payroll run dan Finance posting yang sudah reconciled. Provider dan rekening beneficiary harus disetujui secara independen sebelum batch dibuat.

Secret harus berupa JSON bank_code, account_number, account_name. Nilai rekening tidak disimpan di database; hanya secret reference dan SHA-256 fingerprint yang disimpan.
Webhook kandidat hr-payroll-provider-webhook memverifikasi HMAC-SHA256 raw body melalui header x-dlice-signature. Provider-specific payout dispatch belum aktif; format signature dan kontrak API harus disetujui bersama provider sebelum deploy.
